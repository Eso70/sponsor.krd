# Search and crawler audit — 2026-10-03

## Scope

Reviewed public rendering, metadata, canonical redirects, host/tenant ownership,
publication/cache checks, robots and sitemap generation, structured data,
sharing images, real links, language declarations, tracking placement, private
route indexing, reverse-proxy routing, and the shared business/platform editor.
The full application checks provide regression coverage outside those paths;
this is not a claim that every possible application defect has been eliminated.

## Resolved findings

| Finding | Change |
| --- | --- |
| Platform public link edits left the root-page cache intact | Shared link mutation invalidation now clears business and platform keys, with owner-scoped parent modification updates. |
| Sitemap lastmod missed destination edits/deletions and branding updates | Link mutations advance the parent timestamp; sitemap projection includes branding modification time. |
| Malformed Linktree identifiers bypassed the pre-stream status gate | Invalid identifiers and unsupported nested public paths return actual 404 responses with noindex. |
| A trailing slash on an image alias could redirect to the HTML page | Canonical redirects preserve the share-image suffix. |

| Legal documents lacked canonical URLs and sitemap discovery | Root legal URLs are canonical and included in the root sitemap; tenant copies are noindex. |
| Sitemap index allocation had no protocol bound | Invalid counts and indexes exceeding 50,000 entries are rejected. |
| Direct production API requests bypass Next's noindex header | Both Caddy host blocks apply API noindex headers. |

No schema changes, Git mutations, production writes, invented business facts,
new tracking engines, crawler-UA security exemptions, or duplicated dashboard
SEO controls were introduced.

## Remaining production acceptance

### Post-deployment check

After the owner reported deployment, live checks confirmed full SEO metadata on
the Wafaye page, but robots/sitemap requests returned HTTP 500. The internal API
returned HTTP 400 because the global request-boundary pipe requires `page >= 1`
while the sitemap caller sent `page=0`. The sitemap API/caller now use the
separate bounded `chunk=0` parameter. Regression coverage preserves ordinary
one-based pagination and the HTTP fixture rejects incorrect chunk requests.
Frontend and backend must both be redeployed with this follow-up fix.
The previously audited Ismail URL returned HTTP 404 in this deployment.

Deploy frontend, backend and Caddy changes together, then repeat the production
audit and validate the deployed Caddy configuration. Caddy is not installed in
this local workspace; its changes are covered by configuration regression tests.
Verify DNS/TLS, hostname-aware CDN caching, WAF behavior and representative
mobile/desktop pages. Submit the correct sitemaps in Search Console and monitor
indexing, crawl errors and real-user Core Web Vitals. Local checks cannot measure
field performance or prove Google's indexing decisions.

Large-company search quality also depends on useful accurate content, reputation
and ongoing operations. Those require real published content and live evidence;
they cannot be created by adding metadata or fabricated structured data.
