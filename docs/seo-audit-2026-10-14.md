# Multi-tenant SEO audit and enhancement

## Confirmed findings

- Public tenant/custom-domain resolution, trusted canonicals, paginated owner-scoped
  Linktree/Form sitemaps, publication checks and shared-cache invalidation already exist.
- Backend normalization removes SEO overrides; the shared drawer has no optional
  SEO settings, category/business type, or descriptive business details.
- Language currently uses a writing-system heuristic with no explicit page preference.
- JSON-LD describes every Linktree as WebPage, regardless of actual profile information.
- Generated share images already use the request-scoped page fetch and local Sorani
  font; retain this implementation and verify PNG dimensions and tenant identity.
- The older SEO document predates the verified custom-domain registry and must be updated.

## Decisions

Extend existing template_config with a versioned, optional, validated `seo` object.
Use one static localized category/business-type catalog and one Node-compatible
validator in the shared package. No schema migration, category-management service,
tenant hardcoding, SEO-only hidden text, or independent metadata engine is needed.
Retain legacy unversioned override retirement; owners can configure the new settings
explicitly. Noindex is a veto, never a way to publish private pages or force thin
content into sitemaps. Categories/details must be visible and user-supplied.

Do not apply production migrations, deploy, restart services, alter DNS/WAF or mutate Git.
Validation will use unit tests and the existing disposable HTTP fixture plus isolated builds.

## Implemented architecture

`packages/types/linktree-seo.cjs` and its typed declaration are the single catalog
and validation boundary. There are 16 categories and 31 optional business types,
with stable IDs and English/Sorani/Arabic labels. New settings live under
`template_config.seo.version = 1`; older pages retain safe automatic behavior.
No existing records were rewritten, categorized automatically or assigned facts.

Both Business and Platform create/edit workflows use the same drawer. Category
and compatible business type follow Headline. Search & page details contains
optional search title/description, noindex, preferred page language, owned social
image, search preview and category-aware details. Existing image upload, crop,
shared inputs/selects and section skeletons are reused. Validation precedes
uploads; incomplete schedules stay visible as drafts and cannot be saved.

Metadata resolves explicit settings, then meaningful existing content, factual
category/location context, then name fallback. Canonicals remain server-owned,
host-validated and query-free. Explicit noindex is reflected in both metadata and
owner-scoped sitemap SQL. A name plus a recognized visible category can qualify
when the description is otherwise a starter prompt; Other does not qualify.
Descriptions alone cannot override availability, publication, archive or owner gates.
Backend updates keep existing permission/approval, timestamp and cache invalidation
paths. Custom domains retain the registry's selected-host policy.

Every template renders supplied category/address/cuisine/services/service area/
opening hours visibly. JSON-LD uses WebPage with Organization by default, Person
and ProfilePage for personal/creator types, and a mapped local-business subtype
only when street and city are supplied. Telephone and known social links reuse
existing destinations. No coordinates, ratings, reviews or offers are invented.
JSON-LD escaping and CSP nonce remain intact. No new public interaction or
tracking pipeline was added.

Preferred page language controls metadata, HTML lang/dir and preview direction.
Automatic language remains the existing writing-system heuristic. No user names
are translated and no hreflang is emitted without equivalent localized URLs.

Social images are owned uploads or generated 1200×630 PNGs. The generated route
still uses the local Sorani font, shared request-memoized page fetch and no remote
image fetch. It now completes rendering before headers, logs failures, returns a
noncached 503 on failure and retries failed font loads. Long titles shrink to fit;
Arabic word runs use reverse flex layout because the bundled renderer does not
provide full browser bidirectional text layout. Stored text/browser metadata are
unchanged. Page revisions refresh generated-image metadata URLs. Arbitrary custom
image dimensions are not falsely advertised as 1200×630.

Uploaded asset claiming was also tightened: an asset already owned by another
business cannot be reassigned. Social image ownership is checked on direct and
approval-executed SEO-only writes, even without a banner update.

Root platform metadata remains separate and localized. The inherited generic
networking description was replaced with the actual platform's existing copy.
Root Organization JSON-LD, legal canonicals, real headings/anchors, host-specific
robots and sitemap infrastructure were retained. No invented service page was added.

## Performance and practical limits

Metadata remains server-generated; no client fetch or JS-only SEO rendering was
introduced. Public data reads are request-memoized and owner-cache scoped, with
live availability rechecks. Sitemap queries filter one owner, paginate at 1,000
rows and retain the existing indexes; no speculative JSON index was added.
Responsive images, eager introduction banners, explicit image dimensions and
local fonts remain intact. Buffered share-image rendering uses bounded text and
one 1200×630 image; it trades small per-request memory for reliable error handling.

No live Core Web Vitals/CrUX improvement is claimed from local builds. Search
ranking, rich-result eligibility and actual indexing depend on content and
external crawlers. Short mixed-language inference remains heuristic; explicit
language resolves ambiguity. Artwork handles ordinary Arabic/Latin word runs,
not the complete Unicode bidi algorithm. Hours represent one daily schedule
over selected weekdays; split schedules are not supported. Multi-location
businesses should use separate meaningful pages rather than invented addresses.

   sitemap and inspect representative URLs. Monitor origin 5xx, crawl/indexing

## Prompt completeness follow-up

The complete prompt was reread against the source. Additional confirmed gaps:

- Generated artwork did not honor an explicit sharing description. It now uses
  the same customization priority as metadata.
- Structured data omitted meaningful visible slogans when Description was a
  generic prompt. It now describes distinct meaningful visible text, never
  substituting hidden SEO copy. Existing X/Snapchat profile links are recognized
  and duplicate sameAs destinations are removed.
- Root Open Graph/Twitter locale and descriptions were implicit. They now use
  the root's localized content explicitly.
- Existing advertising service/video-code routes lacked canonicals and localized
  sharing locale. They reuse one metadata builder and trusted public origin.
  Their HTML language respects the visitor language. No new marketing page or
  service was invented, and no Pixel was added.
- The service loader was not explicitly request-memoized. Metadata/body now share
  the same read; HTTP assertions verify one advertising API call per page request.
- Approval execution updated Linktree JSONB but did not purge public body caches.
  It now collects owner-scoped old/current identifiers inside the transaction and
  purges their business/root cache keys after commit. Direct Linktree/link edits
  reuse the same key helper; slug changes clear previous identifiers too.
- The live crawler audit ignored social-image HTTP failures and loosely checked
  canonical presence. It now validates the actual canonical tag, same-origin
  social response/MIME, generated PNG dimensions, and reports bounded timing and
  transfer-size observations. Both actual live pages still have 502 image errors.

Follow-up verification: 11 frontend suites / 84 tests, 12 backend suites / 71
tests, frontend/backend lint, source TypeScript and both isolated builds passed.
The HTTP suite now also covers root/service languages, canonicals, marketing
Pixel exclusion and request memoization. A concurrent build/fixture run hit a
transient Next generated-manifest JSON error; builds and HTTP checks must run
sequentially because generated workspace type files are shared despite separate
distDir. The final sequential HTTP run passed, including root/service pages in
all three languages and the one-read-per-request service assertion.

Additional files: shared public cache helper and its Linktree/link/approval callers,
approval SEO regression test, backend persistence/cache tests, advertising metadata
builder/tests, both advertising route entry points/server loader, root metadata/
layout, expanded HTTP fixture and production audit script. No migration was added.

## Final acceptance review

The final copy of the complete prompt was checked again against implementation
and verification. Two additional edge cases were fixed: the shared validator now
rejects non-string time values instead of permitting JavaScript regex coercion,
and rejects falsy non-string category/type/image inputs. The business-details
editor keeps previously authored fields and incomplete hours editable even when
the owner clears or changes the category. No saved values are silently deleted.
Other/custom categories retain WebPage structured data without assuming an
Organization. The additional metadata regression suite passed all 20 tests.

Final regression checks for these edits passed: 3 frontend suites / 44 tests and
3 backend suites / 18 tests, plus both lint checks and isolated frontend/backend
builds. The final sequential HTTP suite also passed. Earlier complete focused coverage remains recorded above. No schema or
production data change was necessary.

The final live read-only check again passed robots, sitemaps, page metadata,
canonicals, JSON-LD and crawlable content on both actual tenants. Both live
share-image URLs still returned Cloudflare HTTP 502, so production social-preview
acceptance remains incomplete. Local source PNG generation passes, but origin
logs/deployed artifact inspection is required to establish the live cause.
No source-only check can prove a fix for an inaccessible production gateway.
Search Console submission and field Core Web Vitals remain owner-operated
post-deployment verification, not completed actions.
